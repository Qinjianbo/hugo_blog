# 从一个 Skill 到一套工作流

前面七篇，一个 Skill 从无到有讲完了：第二篇写出第一个 Skill，第三篇让它渐进加载，第四篇让它跨工具复用，第五篇让几个 Agent 并行，第六篇用 Router 管起来，第七篇给它立了安全审计的规矩。一个 Skill 是一项本事，但每天真正要跑的，是一件完整的事：从你说一句话开始，到东西交出来为止，中间要过好几道手。

这一篇把前面七篇拼起来：**工作流不是 Skill 的堆叠，而是几个 Skill 按固定顺序排好队，每一步交什么、谁说了算、卡住怎么办都写死，一句话触发就能跑完。** 这也是这个系列的最后一篇，讲完你手里就有一套完整的东西：从写一个 Skill，到跑一套每天都能用的流程。

## 一、工作流和一堆 Skill 有什么不一样

手里有十个 Skill，不等于有一套工作流。差别在三处，缺一个都跑不起来：

- **顺序是固定的。** 工作流里先干什么、后干什么写死了，不用每次现想：先检查文字，再检查链接，最后汇总。顺序一变，结果就可能变，所以顺序本身就是流程的一部分，不是每次临场发挥。
- **交接是固定的。** 每一步交给下一步的东西，格式先定好：检查交回来的是一张表，表里每条只有通过或不通过两种结果。格式不定，收回来就得现猜，第六篇讲的 Router 拼表也拼不起来。
- **停下的地方是固定的。** 哪一步通不过就停、停下来问谁，事先写好：审计通不过就停下来问你，检查出问题就退回重做。没有固定停点的工作流，错了也会一路跑下去，最后交出来的东西没人敢用。

反过来想也一样：**顺序、交接、停点这三样写死了，Skill 才从“会干活”变成“能把事办成”。** 没写死之前，你手里的只是一套工具箱；写死了，才是一条每天能跑的流水线。

## 二、一套每天能跑的工作流长什么样

拿这个系列里反复用的例子说：每天发一篇文章，从你说一句话到文章发出去，工作流是这样跑的：

1. 你只说一句话触发：“检查一下这篇待发文章。”这一句话就是工作流的开关，开关固定，流程才不用每次重新讲一遍。
2. Router 接到之后先拆：拆成文字、链接和图片、分类和标签三份，每份带齐四样东西——做什么、用什么材料、交什么格式、什么时候交，派给三个 Worker。
3. 三个 Worker 同时开工，各查各的，只写自己那一份，互相不直接说话。有问题报给 Router，由 Router 决定重做还是换人。
4. 三份结果收回来，Router 先对格式再拼成一张总表，然后翻安全审计 Skill 过一遍：这篇文章要发布，是不可逆的事；文里有没有秘密信息；收件人和发布位置对不对。审计通不过，流程就停在这里，不往下走。
5. 审计通过了，总表交给你：哪条通过、哪条不通过、不通过的要怎么改。发不发由你决定，你点头了，文章才发布。

这五步里，前面七篇的东西都在：第二篇的检查 Skill、第三篇的渐进加载、第五篇的并行规矩、第六篇的 Router、第七篇的安全审计。**工作流没有讲新东西，它只是把已经讲过的东西按固定顺序排好队。** 所以搭工作流不用从头学，只用把手里已有的 Skill 排一遍。

## 三、让工作流自己转起来的三个习惯

流程搭起来只是第一步，让它每天自己转起来，还要三个习惯：

- **触发的话固定下来。** 同一件事，每次用同一句话触发，写进工作流的开头。话一固定，Router 就不用每次重新听明白你要什么，你也不用每次重新讲一遍要求。触发的话越短越好，能一句话说清的，不要写成一段。
- **跑完记一笔，改 Skill 不改人。** 每次跑完记下哪里卡住了：是 Skill 的触发条件写窄了，还是 Router 派活时四样东西没给齐，还是审计的标准太含糊。卡住的地方，改文件里的那一条，不要靠下次“记得小心点”。工作流是越跑越顺的，前提是每次的教训都落回文件里。
- **一次只改一处。** 工作流想加东西，先加一个 Skill 或者改一个顺序，跑顺了再加下一个。一次改三处，跑不通的时候不知道是哪一处的问题。流程小的时候改起来便宜，等它长大了再改，每一处都牵着别的步骤。

还有一条底线：**工作流越短越好。** 三到五步就能跑完的事，不要写成十步。步数一多，每一步的交接都可能出错，查起来也费劲。先让短的流程跑顺，真的不够用了再往上加。

## 四、动手：把发文章前检查跑成一套工作流

把第二篇的发文章前检查，和第六篇的 Router、第七篇的安全审计拼成一套完整的工作流，目标是：你只说一句话，检查、审计、汇总、发布全跑完，中间你只在最后点一次头。

1. 先写下这套工作流的五步，照着第二节的样子：触发一句话、Router 拆三份、三个 Worker 并行检查、收回来拼总表加安全审计、交给你点头再发布。五步写在一张纸上，每一步后面写清楚交什么格式、卡住停在哪里。
2. 把第二篇的检查 Skill 和第七篇的安全审计 Skill 各自检查一遍：触发条件写得够不够宽，检查清单的通过标准够不够具体。工作流跑不通，问题多半出在这两个地方，而不是 Router 身上。
3. 照着这张纸跑一次：你说“检查一下这篇待发文章”，让 Router 拆、Worker 查、总表拼出来、审计过一遍，最后把总表交给你。你只在最后一步点头，中间一次也别插手。
4. 跑完记一笔：哪一步花的时间最长，哪一步你忍不住想插手，原因写下来。花时间最长的地方，下次把材料提前备好；忍不住插手的地方，说明那一步的交接还没写清楚，改文件，不改你的习惯。

练完这一次，对照一下：你只说了两句话，一句触发、一句点头，中间的事全是流程在跑。如果哪一步还得你亲自下场，问题一般不在你身上，而在流程里：要么顺序没排好，要么交接没写死，要么停点没划清。

## 练一次：把你手头一件常做的事写成工作流

找一件你每周都要做两三次的事，不用是发文章，什么都行。先写成五行的流程：

1. 触发的那句话是什么：每次用同一句话开头。
2. 拆成哪几步：三到五步，每步做什么、交什么格式。
3. 每步是谁干：你自己、一个 Worker，还是 Router 派出去的几个人。
4. 卡住停在哪里：哪一步通不过就停，停下来问谁。
5. 最后交出来的是什么：是一张表、一篇文章，还是一个决定。

写完先跑一次，跑完只改一个地方：跑的过程中最别扭的那一步。改完再跑一次，别扭的地方少了，这套工作流就立住了。以后这件事你就不用每次重新想一遍，流程会替你想。

## 写在最后：从一个 Skill 到一套工作流

八篇走下来，路线其实很短：第一篇认识 Agent Skills，第二篇写出第一个 Skill，第三篇让它渐进加载，第四篇让它跨工具复用，第五篇让几个 Agent 并行，第六篇用 Router 管起来，第七篇给它立规矩，第八篇把它们排成一套每天能跑的工作流。

起点是一个 SKILL.md，终点是一句话就能跑完的流程。中间没有哪一步需要你一次学会很多东西，每一篇只解决一个问题，练一次只改一个地方。

接下来不用急着再学新东西：先挑一件你每周都要做的事，照着这一篇的样子写成五步工作流，跑上两三次。跑顺了，你手里就不只是一个 Skill，而是一套替你干活的流程。这个系列到这里就讲完了，剩下的，是你自己的那套工作流。
