上一回，filesystem 和 fetch 两个参考 Server 已经在终端里跑起来了。但终端里手动起 Server 只能验货，真正用起来，要让每天用的工具去起它们。这一篇把同一套 Server 接进三个地方：Claude Code、Codex、ChatGPT。协议是同一个，配法是三种，差别只在配置文件放哪、用什么格式。

## 一、先看一张对照表

|  | Claude Code | Codex | ChatGPT 网页版 |
| --- | --- | --- | --- |
| 配置放哪 | 项目里的 `.mcp.json`，或 `~/.claude.json` | `~/.codex/config.toml`，项目里是 `.codex/config.toml` | 没有配置文件，在设置 → 插件/连接器里建 |
| 格式 | JSON，`mcpServers` | TOML，`[mcp_servers.名字]` | 表单里填名字、地址、认证方式 |
| 怎么加 | `claude mcp add` | `codex mcp add` | 点几下鼠标 |
| 本地 Server 能接吗 | 能，stdio | 能，stdio | 不能，只能连远程 |
| 怎么看接上了没有 | `claude mcp list`，会话里打 `/mcp` | `codex mcp list`，终端里打 `/mcp` | 新对话里打 `@` 选插件 |

**最关键的一行是“本地 Server 能接吗”。** Claude Code 和 Codex 都跑在你的电脑上，能直接起本地进程；ChatGPT 网页版跑在 OpenAI 的服务器上，够不着你电脑里的东西。所以 ChatGPT 那一节的重点不是配文件，而是怎么搭一座桥。

## 二、Claude Code：一行命令，三个作用域

Claude Code 不用手写 JSON 加 Server，一行命令就行。把上一回的 filesystem 接进来：

```bash
claude mcp add --scope project filesystem -- npx -y @modelcontextprotocol/server-filesystem ~/Desktop/mcp-playground
```

`--` 前面是 Claude Code 自己的参数，后面是起 Server 的命令，照抄上一回终端里跑过的那条。远程 Server 换一种写法：

```bash
claude mcp add --transport http notion https://mcp.notion.com/mcp
```

`--scope` 决定这条配置写进哪个文件、谁能看到：

| 作用域 | 写进哪里 | 谁能看到 |
| --- | --- | --- |
| `local`（默认，不写就是它） | `~/.claude.json`，只挂在当前项目下 | 只有你，只有这个项目 |
| `project` | 项目根目录的 `.mcp.json` | 克隆这个仓库的人都会拿到 |
| `user` | `~/.claude.json` | 只有你，所有项目都能用 |

**最容易踩的坑是默认作用域。** 不加 `--scope project`，配置写进了 `~/.claude.json`，项目里看不到 `.mcp.json`，不是没加上，是放错了地方。团队共用的 Server 用 `project`，只属于你自己的用 `user`。

`.mcp.json` 也可以手写，内容和 Claude 桌面版的配置文件是一个形状：

```json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-filesystem",
        "/Users/你的用户名/Desktop/mcp-playground"
      ]
    },
    "notion": {
      "type": "http",
      "url": "https://mcp.notion.com/mcp"
    }
  }
}
```

注意两处：远程那一项必须写 `"type": "http"`，只写 `url` 不写 `type` 会被当成 stdio Server，直接报错跳过；密钥别写进文件里，写环境变量的名字，比如 `"GITHUB_TOKEN": "${GITHUB_TOKEN}"`，每台机器自己提供值，`project` 作用域提交进仓库也不会泄密。团队里有人第一次拉到这个文件，Claude Code 会先问他批不批准，批了才跑。

接上之后，在会话里打 `/mcp`，能看到 Server 和它暴露的工具，就说明通了。

## 三、Codex：TOML，一个文件三处共用

Codex 不读 `.mcp.json`。它的 Server 全写在一个 TOML 文件里，默认是 `~/.codex/config.toml`。加 Server 同样一行命令：

```bash
codex mcp add filesystem -- npx -y @modelcontextprotocol/server-filesystem ~/Desktop/mcp-playground
```

远程 Server 用 `--url`：

```bash
codex mcp add example --url https://mcp.example.com/mcp
```

这两条命令实际写进 `~/.codex/config.toml` 的是这样：

```toml
[mcp_servers.filesystem]
command = "npx"
args = ["-y", "@modelcontextprotocol/server-filesystem", "/Users/你的用户名/Desktop/mcp-playground"]

[mcp_servers.example]
url = "https://mcp.example.com/mcp"
```

远程 Server 要带密钥的，写环境变量的名字，不写值本身：

```toml
[mcp_servers.example]
url = "https://mcp.example.com/mcp"
bearer_token_env_var = "EXAMPLE_API_TOKEN"
```

Codex 里这个文件还有个好处：**ChatGPT 桌面版、Codex CLI、IDE 插件三处读的是同一份配置**，配一次，三处都有。反过来也一样，TOML 写错一个符号，三处一起读不到，所以优先用 `codex mcp add` 写，少手改。

项目里也可以放一份 `.codex/config.toml`，只对这一个项目生效，但前提是这个项目在 Codex 里是受信任的——不受信任的项目会直接跳过它。查接上没有：`codex mcp list` 看配置，终端里打 `/mcp` 看当前会话里活着的 Server。远程 Server 要走 OAuth 的，用 `codex mcp login 名字` 单独登录。

## 四、ChatGPT：网页版只能连远程，本机要走桥

ChatGPT 网页版没有配置文件，也没有 `mcp add` 这样的命令。它的入口在设置里，但菜单名字这半年变过几次：2026 年 7 月 9 日，OpenAI 把应用目录并进了统一的插件（Plugins）目录，老教程里的入口很多已经对不上了。按 2026 年 11 月 11 日复核过的 OpenAI 帮助中心说法，现在的路是：打开插件页，点加号，选“添加自定义 MCP Server”，填名字、公开的 HTTPS 地址、认证方式，读完风险提示点继续，建成插件后装上，新对话里打 `@` 选它。另一些 2026 年 9 月前后的教程还写着要先在“设置 → 安全与登录”里开开发者模式（Developer Mode），再去连接器里创建——如果你按新入口走，找不到开发者模式的开关是正常的，不是你的账号有问题，菜单改了而已；按你眼前实际看到的入口走。

不管走哪个入口，有三条硬限制：

**第一，必须是远程 Server。** ChatGPT 是从 OpenAI 的服务器上调你的 Server，地址得是公开的 HTTPS 端点，讲 SSE 或 Streamable HTTP。`localhost`、你家里的内网地址，它都够不着。

**第二，要付费计划。** 个人账号要 Plus、Pro 这类付费计划，Business、Enterprise、Edu 要工作区管理员放行自定义连接器。免费账号看不到这个入口是正常的。

**第三，按对话启用。** 装好插件不等于每句话都能用，新对话里要先把这个插件选进来，工具才进上下文。

那本机的 filesystem、fetch 怎么接进 ChatGPT？搭一座桥。localmcp 就是干这个的：它在本机起一个服务，主动用 WebSocket 连到 Cloudflare Worker 中继，ChatGPT 调的是中继上的公开地址，中继再把请求转回你本机。**本机不用有公网 IP，也不用开入站端口**，是你这边主动连出去。

```bash
npm install -g @daodao97/localmcp
localmcp
```

看到 `Status: running` 后，复制 `MCP URL:` 后面的完整地址。然后去 ChatGPT 设置里开开发者模式，进插件页新建一个连接器：名字填 `LocalMCP`，服务器 URL 粘贴刚才复制的完整地址，身份验证选 None。新建对话，输入 `@` 选 LocalMCP，问一句“列出本机工作区的路径和根目录下的文件，不修改任何内容”，返回目录列表就是通了。

localmcp 默认的工作区就是你的用户主目录，文件、Shell、持久进程三个工具默认全开，配置在 `~/.localmcp/localmcp.json` 里。练手的话，先把工作区改成上一回那个沙盒 `~/Desktop/mcp-playground`，别直接拿主目录开刀。它的 MCP URL 里含访问凭证，**别发到群里，也别留在截图里**。以后想换中继、想在里面再挂别的 MCP Server，都是改这个配置文件，不用重走一遍 ChatGPT 那边的流程。

## 五、一份配置，三处不要直接复制

同一个 filesystem Server，三种写法摆在一起，差别一眼就能看出来：

- Claude Code 的 `.mcp.json` 是 JSON，`command` 加 `args` 数组，环境变量写 `${VAR}`。
- Codex 的 `config.toml` 是 TOML，`[mcp_servers.filesystem]` 一张表，`command` 加 `args` 数组，密钥写变量名 `bearer_token_env_var`。
- ChatGPT 网页版没有文件，地址和认证方式填在表单里；本机 Server 得先过 localmcp 变成远程地址。

**抄格式，别抄密钥。** 密钥永远只出现在你自己电脑的环境变量里，不出现在提交进仓库的 `.mcp.json`、不出现在发给别人的配置截图里、不出现在 localmcp 的 URL 转述里。提交 `.mcp.json` 之前先打开看一眼，有没有哪一行是真密钥；Codex 的项目级配置只在受信任的项目里生效，换台电脑、换个项目，先确认信任状态再查为什么没加载。

## 练习：20 分钟，把第 2 篇的 Server 接进日常工具

1. 在 Claude Code 里跑 `claude mcp add --scope project filesystem -- npx -y @modelcontextprotocol/server-filesystem ~/Desktop/mcp-playground`，打开项目里的 `.mcp.json` 看一眼写进去的东西，再打 `/mcp`，问一句“列一下 mcp-playground 里有什么”。
2. 在 Codex 里跑同样意思的 `codex mcp add`，打开 `~/.codex/config.toml`，对照着看 JSON 和 TOML 同一件事的两种写法。
3. 打开 ChatGPT 的插件页，看一眼你的账号上有没有“添加自定义 MCP Server”这个入口，记下它现在叫什么、藏在哪一级菜单里——不用真的加，先摸清入口。想真接本机，再按第四节走 localmcp。

## 安全提示

配置文件也是攻击面。**别人发来的 `.mcp.json`、`.codex/config.toml` 别直接粘贴就用**，先看它要起什么命令、要读哪个文件夹、要连哪个地址——那是一段会在你电脑上执行的命令，不是普通的设置。ChatGPT 里接的 Server 是在 OpenAI 的服务器上被调用的，写操作先在小范围试，别一上来就给它能改生产数据的工具。第 6 篇会把这些风险一次讲透。
