模型本身只会聊天。它要查数据、改文件、调工具，得有人把外面的世界接进来。以前每个应用各接各的：ChatGPT 接一套，Claude 接一套，Cursor 再接一套，同一个工具要写三遍。MCP 就是把这个接法统一成一个标准。这一篇先把三件事讲清楚：MCP 是什么、三件套怎么分工、它和直接调 API 有什么不一样。

## 一、为什么模型需要一根“数据线”

大模型再强，也只能处理你发给它的那段话。它不知道你电脑里有什么文件，不知道你邮箱里有什么邮件，也调不动你公司的系统。想让它干活，要么你把东西复制粘贴给它，要么有人写代码把外面的世界接进来。

以前的接法是各接各的。每个应用自己写对接代码：ChatGPT 写一套，Claude 写一套，Cursor 再写一套。工具那边也一样：同一个文件系统，给三个应用要做三个版本。接得越多，维护的人越累，最后只有大公司接得起。

MCP 要解决的就是这个重复劳动。Anthropic 在 2024 年 11 月把它开源出来，2025 年 12 月捐给了 Linux 基金会，现在由中立的基金会管。它定了一个统一的规矩：模型这边只管按标准问，工具那边只管按标准答，中间的线大家共用。

**MCP 不是一个新的模型，也不是一个新的应用，它是模型和工具之间的通用插头。**

## 二、Host、Client、Server 三件套

MCP 里只有三个角色，记住它们的名字，后面七篇全是它们的排列组合。

**Host 是你用的应用。** 比如 Claude 桌面版、ChatGPT、Cursor、VS Code。它是房子，住着模型，也管着权限：哪个 Server 能接、每次调用要不要你点头，都是 Host 说了算。

**Client 是 Host 里负责跟某个 Server 说话的连接。** 一对一，一个 Client 只连一个 Server。你接了五个 Server，Host 里就有五个 Client 在跑。

**Server 是真正干活的那头。** 它对外暴露三样东西：工具（Tools）、资源（Resources）、提示词（Prompts）。这一篇先知道名字，分工在第 4 篇细讲。Server 可以跑在你自己的电脑上，也可以跑在远端。

数据怎么走，是一条单行道：模型想查东西，先告诉 Host；Host 通过 Client 去问 Server；Server 干完活，把结果原路送回来。**模型自己不直接碰你的文件和账号**，中间隔着 Host 的权限检查。这一点后面讲安全时会再回来。

## 三、MCP 和直接调 API 有什么不一样

直接调 API 是点对点的私线。每个应用自己写对接代码，换个应用重写一遍；权限、格式、报错各不相同。一个工具想让五个应用都能用，就要写五遍。

MCP 是大家都认的通用插座。对接代码只写一次，任何支持 MCP 的应用都能用同一个 Server。工具长什么样、要什么参数、安不安全，都有统一的描述格式，Host 读了就知道怎么调用、要不要先问你。

它和 Function Calling 也不是一回事。Function Calling 是模型“会喊工具”，解决的是模型的能力问题；MCP 是“工具放在哪、怎么被发现、怎么被安全地喊”，解决的是工具的供给问题。一个管喊，一个管供货。

**API 是私线，MCP 是插座。私线快，插座通用。**

## 四、这个标准现在有多大

先看官方口径。2025 年 12 月 9 日的 MCP 博客说：SDK 每月下载 9700 万次，公开 Server 1 万多个；ChatGPT、Claude、Cursor、Gemini、Copilot、VS Code 都已经支持 MCP。

再看 2026 年 11 月的第三方跟踪。11 月 15 日的数据：TypeScript 和 Python 两个 SDK 30 天下载合计约 6.56 亿次，官方 Registry 登记的 Server 有 64,935 个，一年前才 2000 个左右。2026 年 10 月 30 日，Ruby SDK 成了第六个 Tier 1 SDK。

但要诚实地说一句：标准跑得比落地快。现行规范是 2026 年 7 月 28 日发布的无状态版，实测只有 0.2% 的 Server 真正讲这个新版，大多数还停在老版本上。这个系列会处处标明版本，免得你按新版配了，老 Server 接不上。

## 练习：20 分钟，摸清你手头的 MCP

1. 打开你常用的 AI 应用，Claude、ChatGPT、Cursor、VS Code 任意一个，找一找它的设置里有没有 MCP、模型上下文协议或者“连接器”这一项，记下来它叫什么名字。
2. 去看一眼 MCP 官方 Registry，搜一个你认识的工具，比如 GitHub、Slack 或者文件系统，看看一个 Server 的页面都写了什么：工具列表、要什么权限、怎么启动。
3. 对照这一篇的三件套，写一句话：你现在用的这个应用是 Host，你想接的那个东西是 Server，中间缺的那根线就是 Client。

## 安全提示

这一系列每篇都会有一条安全提示，先立一条总规矩：**MCP Server 是往你电脑和账号里伸手的东西，接之前先看它要什么权限、是谁发布的。** 来路不明的 Server 不接，第 6 篇会专门讲风险。
